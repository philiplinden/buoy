# 2026-08-08 - `no-avian`

Revisiting this project after a long while. I have a few new insights to bring
that will hopefully get us unstuck.

The first insight is to drop `avian` physics package. Avian is designed and
optimized for _collision detection_. It has other features like forces,
friction, meshes, and others, but all are designed in service of managing
collisions between objects.

Buoy needs to manage forces, and collisions are almost never going to happen
(except for self-collisions I guess). Geometry-dependent systems like buoyancy
and drag can use collision tools to compute forces and mesh normals or 
intersections, but there are other ways to compute forces that don't require
collision detection.

Mass properties is another useful feature in Avian, but we already have to do
some magic to get it working for the ideal gas volume, so it isn't adding much
value in the end.


I think there will be one more major refactoring to do: `buoy-runtime` is...
well, I don't like it very much. It's clunky and annoying to maintain. The two
main crates for this project are the physics engine (check) and the editor / ui
(check). I have the runtime there for headless operation, but I can bake that
into the physics engine crate itself without much drama.
